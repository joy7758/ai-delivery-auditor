# 数量相同，金额和明细却错了

以下根据 2026 年 10 月 16 日的本地原始运行记录整理，并去除本机路径、会话标识等内部信息。它是结果节选，不是完整原始报告，也不是第三方认证。演示数据为原创合成材料，缺陷由制作方预置；这不是客户案例或盲测。

## 1. 同一份要求，两版结果

| 检查项 | 初版实测 | 返工版实测／要求 |
| --- | --- | --- |
| 订单数 `count` | 3 | 3 |
| 金额 `total_cents`（分） | 11504 | 1505 |
| 编号 `ids` | A01、A02、A04 | A01、A03、A04 |
| 原有 4 项测试 | 1 项通过、3 项失败 | 4 项全部通过 |

取消订单 A02 被误计，0 分已付款订单 A03 被遗漏，数量一增一减恰好抵消。单看“3 单”无法判断交付正确。

## 2. 首次检查：问题和修改建议

| 要求 | 当时的观察 | 反馈给开发执行者的修改方向 |
| --- | --- | --- |
| 只计精确 `paid` | 初版筛选条件是排除 `pending` 且金额大于 0；取消订单、部分异常状态仍被纳入 | 改为精确匹配 `paid`，不擅自转换大小写或去空格 |
| 保留 0 分已付款订单 | A03 未出现在结果中 | 取消金额必须大于 0 的筛选，保留整数计算和输入顺序 |
| 完整样例须符合要求 | 数量为 3，但金额 11504、明细含 A02 | 复查完整输出，不改数据或测试期望迁就错误 |
| 完成说明有依据 | 交付说明声称“四项测试均通过”，当前实际为 1 过 3 失败 | 修复后真实重跑，再更新说明，写清未测范围 |

原 4 项测试的首轮状态：

```text

test_exact_status_zero_and_integer FAIL
test_no_paid                       FAIL
test_sample_cli                    FAIL
Ran 4 tests — FAILED (failures=3)
```

这是当前文件与当前完成说明发生冲突的证据。旧版是否曾经运行过其他测试，没有记录可确认，不能据此判断开发者故意编造。
