# AI开发交付审计官

**帮你发现 AI 开发跑偏，并把工作拉回原要求。**

你提出的要求，AI 可能漏做、做错，或者还没做好就说完成。我们原创设计了这款 Skill，帮你对照原要求检查当前成果，列出修改清单；开发者改完后，再检查一次。

你会得到：哪些要求做到了、哪里偏了、建议怎么改，以及哪些还没查清。

适合用 AI 做网站、脚本和小工具的人。每完成一个阶段，或准备交付时，按需调用它检查。Skill 可以理解为给 AI 助手使用的一套工作步骤。

用法：给出原要求和当前文件 → 按问题清单修改 → 检查新版本。

本仓库提供产品介绍、使用说明和虚构案例，不含完整 Skill 或核心源码。

[怎么使用](docs/usage.md) · [看订单统计案例](examples/order-summary/audit-excerpt.md) · [常见问题](docs/FAQ.md)

## 什么时候用

- AI 说程序写完了，你想检查是否真的按要求完成。
- 网站、脚本或小工具已经交付，你想知道还有哪些地方需要修改。
- 开发者说问题改好了，你想再核对一次。

它适合交付前的代码检查、需求核对和修改后复查，可以在需要时调用，不必每做一步都检查。

## 怎么用：检查、修改、再检查

1. **给要求和文件。** 告诉它要做什么，程序在哪里；有测试或完成说明，也一起提供。
2. **拿到问题清单。** 它说明问题在哪个文件、为什么不符合要求、建议改什么。能运行且获准运行的测试才会实际执行。
3. **让原开发者修改，再复查。** 把清单交给原来写程序的 AI 或开发者；改好后检查新版本，保留之前的问题记录。

例如，你会收到这样的反馈：

> **有问题：零金额的已支付订单被漏掉了。** 需求要求保留这类订单，但当前筛选条件把它们排除了。请修改筛选条件，再运行对应测试。

没有运行条件时，会明确写“未核实”，不会把没测过的内容说成通过。[这里有可直接复制的三段话术](docs/usage.md)。

## 我们做过什么验证

我们用虚构订单制作并实际运行了一次演示，事先放入了已知错误：程序误算了一笔取消订单，还漏掉了一笔零金额的已支付订单。

| 检查内容 | 修改前 | 修改后 |
| --- | --- | --- |
| 订单数量 | 3 笔 | 3 笔 |
| 统计金额 | 错算为 115.04 元 | 正确为 15.05 元 |
| 原有 4 项测试 | 1 项通过、3 项失败 | 4 项全部通过 |

数量碰巧一样，并不代表统计正确。审计官把问题列出来，由原开发者修改一次，再检查修改后的程序。[查看问题与复查结果](examples/order-summary/audit-excerpt.md)。

这是我们原创的本地演示，不是真实客户案例，也不是不知道错误位置的盲测。它说明这次流程跑通了，不证明能找出所有问题或比其他 AI 更准确。

## 从哪里开始

**当前这个 GitHub 仓库提供介绍、用法和案例，不含完整 Skill 或安装包，克隆仓库不能直接启用。**

公开体验包正在准备 Red Skill 发布。平台的用法是：获取安装口令 → 交给本地 AI 助手安装 → 提供要求和待检查文件。可用入口会在实际审核、安装验证后补充；未提供入口前，请勿把本文当作已上架通知。

已经接入本产品的用户，可直接按[使用说明](docs/usage.md)调用。目前已有验证来自 **Mac＋Codex 本地环境**；其他系统和 AI 助手尚未实测。

## 使用前知道这几件事

- 它帮助检查和反馈，程序修改由原开发者完成；不会在后台持续监控。
- 结论只针对本次文件和实际检查的内容，不能保证查出所有错误，也不代替你的最终验收。
- 使用需要你自己的 AI 助手、模型额度和文件权限。公开体验包不包含完整包的程序版本核对工具。
- 只提供有权交给当前 AI 环境处理的材料；公开反馈请用虚构数据，不提交密钥或客户资料。
