# 怎么用

以下话术用于**已获得相应权限，并完成产品接入的环境**。当前已做本地验证的是 Mac＋Codex。此文档仓库不包含完整 Skill 或安装包，克隆本仓库不能直接启用产品。

## 第一次：说明目标，先只读检查

提供这次的目标、仍然有效的补充要求、当前成果位置和允许检查的范围。已有测试或历史版本时一并提供，缺失的材料据实说明。

> 请用 AI开发交付审计官检查这次成果。目标是【目标】，仍有效的补充是【补充】，当前成果在【位置】。允许读取【范围】，先不要修改文件。请告诉我哪些要求已满足、哪些有问题、哪些还缺证据，并给出问题位置、依据和修改清单。不要把未测试写成通过。

若宿主找不到该 Skill，先核对当前接入状态；不把模型的一般回答当作产品已调用。本文不提供未经验证的远程安装或下载命令。

## 第二次：由开发执行者返工

把问题清单交给有修改权限的开发执行者。审计请求本身不代表授权修改文件。修复后留下新版本和实际自查结果，保留旧版问题记录。

## 第三次：对新版本重新复验

> 请用 AI开发交付审计官复验【新成果位置】。原问题记录在【位置】，本轮修改针对【问题】，目标和有效补充为【内容】。请先只读检查这些问题是否解决、相关功能是否受影响；保留旧版失败记录，不要直接沿用旧版的通过结论。缺少证据的部分请说明。

最终结果应能回答：检查了哪一版、依据哪些要求、发现了什么、哪里还未知、下一步由谁处理。

不需要每做一步都审计。可以在需求确定、阶段交付、重要修改和返工完成等关键节点按需使用；它不是持续监听的后台服务。
