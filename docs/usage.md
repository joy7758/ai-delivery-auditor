# AI 写完程序后，怎么检查和复查

AI开发交付审计官是我们原创设计的 Skill，帮助你对照要求检查程序，拿到问题清单，再检查修改结果。

## 先确认能用

你需要一个能读取待检查文件的 AI 助手，并接入该 Skill。目前已有验证来自 Mac＋Codex 本地环境；其他环境尚未实测。

本 GitHub 仓库只有介绍和案例，不含安装包。公开体验包正在准备 Red Skill 发布；审核和安装验证完成后才会提供入口。Red Skill 提供安装口令，使用者把口令交给本地 AI 助手安装，检查也在该 AI 环境中进行。

已经接入后，先让 AI 确认“已读到 AI开发交付审计官 的 Skill 文件”。找不到时先解决接入问题，不能把普通聊天回复当作已经调用成功。

## 准备三样东西

1. **你的要求：** 原本要做什么，哪些补充要求仍然有效。
2. **当前文件：** 程序、完成说明、已有测试；没有的材料直接说明。
3. **允许的操作：** 可以读哪些文件，是否可以运行测试，记录保存在哪里。

## 第一步：让审计官检查

把下面的话发给已接入的 AI 助手，替换括号里的内容：

> 请用 AI开发交付审计官检查这次程序。我的要求是【要求】，文件在【位置】，允许读取【范围】。先不要修改程序。请逐条告诉我：哪些已满足，哪些有问题，哪些还没查清。每个问题写明对应文件或行号、为什么不符合要求、建议改什么。报告另存到【目录】，不要覆盖旧报告。没有实际测过的内容不要写成通过。

需要运行测试时，明确补充：

> 可以在【隔离的测试目录】运行【指定测试命令】。不要联网、安装依赖或读取范围外的文件。

你会得到一份检查报告和可交给开发者的问题清单。缺少关键材料时，会说明缺什么。

## 第二步：让写程序的 AI 或开发者修改

把问题清单交回原来的开发对话：

> 请按【问题清单位置】修改【程序位置】，只处理清单内已确认的问题，不增加新功能。保留旧版本，修改后的文件放到【新位置】。运行已获准的测试，并说明改了哪里、实际结果是什么。

审计官负责检查；这段话才是在给开发者安排修改。

## 第三步：检查修改后的版本

回到审计对话：

> 请用 AI开发交付审计官复查【新版本位置】。原要求在【位置】，上一轮问题在【位置】。请重新读取新文件，检查这些问题是否解决，以及相关功能是否受影响。另存新报告，保留旧失败记录。没有重新检查的内容请写清楚，不要沿用旧版本的通过结论。

复查后，你应能看懂：查的是哪一版，哪些问题解决了，哪些还要改，哪些仍缺材料。是否接受交付，由你决定。
