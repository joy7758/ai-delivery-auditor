# 常见问题

## 它和写代码的 AI 怎么配合？

开发执行者负责实现和返工；审计官围绕要求检查当前成果，给出有依据的问题和修改清单。开发者改完后，审计官再检查新版本。审计者仍可能漏查、误判，需要环境、工具和材料支持。

## 能防止跑偏吗？

它帮助把成果拉回已确认的目标，发现偏差后说明依据，返工后再复验。不能保证发现所有问题，也不会自动持续监控或自动修复。

## 没有发现问题，也会强行挑错吗？

不会。必要检查完成且没有发现有据问题，就结束该轮。缺材料、权限或环境时，说明尚不能判断的部分，不把它写成通过。

## 通过了，就是整个项目没问题吗？

通过只覆盖本轮目标、当前版本和已执行的检查。没有测过的系统、输入边界、性能或安全问题不能据此推定通过。改了新版本也需按相关范围重新检查。

## 为什么示例里数量一样，结论却不同？

一笔取消订单被错误计入，一笔 0 分已付款订单被遗漏，数量恰好抵消。金额和编号列表能揭示错误。详见[案例节选](../examples/order-summary/audit-excerpt.md)。

## 下载这个仓库就能用吗？

不能。本仓库提供说明、合成示例和历史结果节选，不交付完整 Skill、程序或产品权益。接入、获取和购买方式暂未在本仓库提供；不能把演示结果当成订阅流程已打通的证明。

## 支持哪些环境？

目前公开说明依据 Mac＋Codex 的本地验证，演示程序使用 Python 3.14.5。使用者还需具备对应模型、工具和文件权限。其他系统、宿主和长期稳定性未验证。
